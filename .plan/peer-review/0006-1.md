# DMS-1408 — Review Triage Summary of 0006

This is a summary of `.plan/peer-review/0006.md` only. It does not re-check code,
tests, history, or the findings themselves.

## Requires review before merge

### T1 — Rebase and regenerate generated DDL (blocker)

`0006.md` reports that the branch is stale against `origin/main`, with 108 merge-conflicted
paths. DMS-1381 rewrote the same DDL emitter and tests, and `origin/main` contains the
MSSQL `FORCESEEK` deadlock mitigation while this branch's generated MSSQL goldens do not.

Decision: the branch must be rebased onto current `origin/main`; DMS-1408 then needs to be
re-applied and the full generated-golden set regenerated. Review the resulting merge/rebase
diff specifically for preservation of DMS-1381's concurrency/deadlock mitigation.

### T2 — Watermark compatibility and release communication (major)

Removing the second sequence allocation changes `newestChangeVersion`: it is now equal to a
newly written document's `ContentVersion`, rather than one value ahead. Since lower bounds are
inclusive, a client that resumes with its previous watermark may receive the boundary document
again.

Decision: product/release owners should decide whether this needs release notes or upgrade
guidance for incremental-extraction clients, and whether the intended client resume semantics
need an explicit public contract. The report treats the behavior as likely correct, but flags
the compatibility communication as missing.

### T3 — Release-scoped mapping-version policy sign-off (review question)

The unchanged effective-schema fingerprint is reported as intentional under the release-scoped
`RelationalMappingVersion` policy, with fresh provisioning as the mitigation for intra-release
physical drift. The report does not call this a defect.

Decision: obtain explicit team/release-management sign-off that this policy is appropriate for
a destructive physical schema change, including its documented requirement to reprovision
databases from fresh generated DDL. No mapping-version bump is requested by this report.

## Needs remediation review

### T4 — Remaining hydration fixture columns (minor)

`HydrationExecutorTests.cs` is reported to retain one `dms.Document` fixture that declares and
inserts `IdentityVersion`; its sibling fixtures and the PostgreSQL counterpart were cleaned.

Action to review: remove the stale fixture-column declaration and insert, then run the affected
hydration tests. This is a test-fixture consistency issue, not a reported production defect.

### T5 — Incorrect natural-key design-doc wording (minor)

`natural-key-resolution.md` is reported to say that the key-change workset causes both a
`ContentVersion` bump and a tracked-change row. The report says the content bump is controlled
by the separate `affectedDocs` stored-column workset; the key-change workset controls only the
tracked-change row.

Action to review: correct the wording so the two worksets and their responsibilities are not
conflated.
