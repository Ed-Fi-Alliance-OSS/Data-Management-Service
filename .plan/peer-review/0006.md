1. Major: the change-queries watermark is no longer one ahead

Found only by the Claude reviewer, and it's the sharpest finding in the round. Dropping the IdentityVersion sequence default removes the second ChangeVersionSequence allocation per write, so newestChangeVersion now equals the just-written document's ContentVersion instead of sitting one value ahead. With an inclusive lower bound (TrackedChangeQueryPlanner.cs:394 → c."ChangeVersion" >= @MinChangeVersion), a client polling with minChangeVersion = previous newestChangeVersion now re-receives the boundary document on every poll.
