# DocumentCache CDC-INV Evidence Matrix

This matrix is the DMS-1317 traceability record for the E18 DocumentCache projection
boundary. Each in-scope row identifies provider-specific evidence, shared or narrower-story
evidence, new DMS-1317 evidence, and an explicit exclusion or follow-up. The paths are
repository-relative so the matrix can be checked without provider databases.

## Scope and ownership

The DMS-1317 evidence scope is `CDC-INV-01` through `CDC-INV-05`, plus `CDC-INV-14` and
`CDC-INV-15`:

- `CDC-INV-01`: configuration, target selection, durable lifecycle, and projection status.
- `CDC-INV-02`: cached document contract and provider-equivalent materialization.
- `CDC-INV-03`: transactional enqueue, freshness, acknowledgement, concurrency, and write
  overhead.
- `CDC-INV-04`: bounded projector execution, baseline, rebuild, restart, and no-scan status.
- `CDC-INV-05`: cache-backed reads, fallback, authorization, direct fill, and concurrency.
- `CDC-INV-14`: repair, rebuild, scrub, cache-ahead recovery, and operational workflows.
- `CDC-INV-15`: security, telemetry, operations, bounded diagnostics, and no-scan status.

`CDC-INV-06` through `CDC-INV-13` are explicitly E19-owned Kafka/CDC connector contracts
(connector topology, topics and records, transformation, pinned runtime, source position,
deployment binding, consumer bootstrap, and retention). DMS-1317 links to the E19 runbook
where an operator workflow crosses the projection boundary, but does not claim connector
implementation or Kafka end-to-end evidence.

Representation restamp implementation and primary restamp tests are owned by DMS-1318
([DMS-1318 story](../design/backend-redesign/epics/18-document-cache/08-representation-restamp-utility.md)).
Current DMS-1317 branch disposition: DMS-1318 has not landed; code search finds no
DocumentCache restamp runtime or CLI implementation under `src/dms`. Until that story
lands, restamp evidence is conditional/blocked and is not fabricated in the rows below;
this is the conditional DMS-1317 evidence disposition.

## Evidence reading notes

- Provider integration tests require their configured PostgreSQL or SQL Server test target;
  the matrix records test identity and path but does not imply that a documentation check
  starts either database.
- `DocumentCacheWriterPerformanceEvidence_it_compares_projector_and_direct_fill_workload_modes`
  is bounded component evidence. DMS-1317 covers the representative-scale qualification
  harness, thresholds, validation schema, and durable-baseline-cursor Jira escalation rule
  in `reference/document-cache/performance-qualification.md`; measured PostgreSQL and SQL
  Server result artifacts are follow-up-ticket scope.
- If DMS-1318 lands before DMS-1317 closes, add follow-up test tasks and evidence for
  Tracking, Disabled, Resetting, Rebuilding, set-latch rejection, API validators, Change
  Query mirrors, cache reads, and status; until then those restamp claims remain
  blocked/conditional.
