# Story: Adapt Tracked Namespace Authorization and Emit Tracked Namespace Indexes

## Description

Authorization Story 22 selects and implements the live PostgreSQL Namespace predicate/index mechanism.
This story consumes that decision for tracked-change queries, explicitly owns any `TrackedChangeAuthorizationSqlEmitter` adaptation needed to make the tracked predicate seekable, and emits per-resource tracked namespace indexes.
It depends on Story 33 and Authorization Story 22, but not on the relationship subject-cardinality rewrite: the runtime ANDs `NamespaceBased` authorization with any relationship OR-group on the same request, so this story's matrix covers combined Namespace-plus-relationship plans, and the A/B against the cumulative baseline isolates the namespace index's marginal effect from relationship-view misestimates already present in that baseline.

## Acceptance Criteria

- Apply the live story's selected PostgreSQL prefix semantics, escaping behavior, generic-plan contract, and operator class to tracked `NamespaceBased` `/deletes` and `/keyChanges` authorization.
- Preserve SQL Server's existing parameterized prefix-`LIKE` behavior unless its isolated checkpoint selects a measured change.
- Extend the tracked-change portion of `DeriveIndexInventoryPass` with one namespace index per tracked table, excluding `SharedDescriptor`, using the selected provider mechanism.
- The indexed column is the table's runtime-probed namespace column: `ReadChangesAuthorizationPlanner.ResolveTrackedNamespaceColumn` walks the resource's declared namespace securable paths in order and probes only the first that resolves, so when a table carries more than one representable namespace column, the derivation applies the same first-resolvable rule and emits no index on a column the runtime never probes.
- Classify namespace columns by either `SourceJsonPath` matching a declared namespace path or `CanonicalStorageColumn` matching the root live column to which that path resolves; coverage must include the key-unification dedup case where the surviving `SourceJsonPath` is an identity path and only the `CanonicalStorageColumn` check identifies the column.
- Coverage is predicate-aware and conditioned on the live story's selected PostgreSQL mechanism. If the selected mechanism requires a pattern-capable operator class, an ordinary equality PK/UK or B-tree must not suppress the required pattern-capable index, while a genuinely compatible operator-class index may deduplicate it; under a documented C-collation deployment requirement, an ordinary B-tree on the same leading column is the compatible prefix access path and ordinary coverage applies. SQL Server retains leading-column coverage.
- Array-nested namespace securables retain the existing tracked root-scope security-configuration behavior.
- Enumerate every candidate namespace index in the harness artifact (roughly 30 tracked tables with a runtime-probed namespace column at current DS 5.2 scale). This story has a single schema-derivable emission predicate (one namespace index per tracked table on its runtime-probed namespace column, excluding `SharedDescriptor`), so adoption is all-or-nothing and every matching table receives its index deterministically, including extension-project resources and tables absent from the benchmark schema; `DeriveIndexInventoryPass` sees only the derived model and never deployment cardinality.
- Stratify the benchmarked candidates by tracked-table cardinality tier and name at least one measured representative table per stratum, including each stratum's largest-cardinality table. Strata and representatives are recorded in the artifact before measurement; they exist to prove the predicate safe across the cardinality range and never participate in the emission rule.
- All read and write comparisons in every phase follow `22-spike-findings.md` § "Tracked-index evidence protocol": environment pinning, both supported SQL Server compatibility levels, workload floors, measurement and noise controls, the seek-use requirement, and the write and per-table baseline storage ceilings.
- Run provider A/B tests with the full candidate overlay applied (with a single predicate this is also its isolated overlay) against the protocol's cumulative baseline (the current generated DDL and shipped runtime predicates, including Story 33's adopted categories and Authorization Story 22's selected mechanism) for resource and descriptor `NamespaceBased` changes, multiple prefixes, escaping characters, null/empty values, case/collation boundaries, and PostgreSQL generic plans. For per-resource tracked tables, cover every representative table's `/deletes` and `/keyChanges` across the five window shapes of the Tier-1 emission story's matrix (no bounds, min-only, max-only, both-bounds full, both-bounds narrow), every cell also recording the separate `totalCount` count statement; require an index seek/prefix-boundary condition and the protocol's required benefit on at least one representative shape in the largest-cardinality stratum, with no measured shape in any stratum above the protocol's regression ceiling. `SharedDescriptor` remains excluded from namespace-index emission, so its cases require functional parity within the protocol's regression ceiling, not a namespace prefix-boundary assertion. Because the runtime ANDs `NamespaceBased` authorization with any relationship OR-group on the same request, the matrix also covers combined Namespace-plus-relationship authorization on at least one representative table per stratum that carries relationship-authorized columns (where the stratum contains such a table), for `/deletes` and `/keyChanges` at single-subject and district-scale relationship-subject cardinalities; the protocol's regression ceiling applies to these combined shapes, gating only regressions the namespace index introduces against the same combined-shape baseline.
- A failed gate in any stratum on either provider blocks the predicate on both providers pending redesign; nothing is emitted from a blocked or unmeasured predicate.
- Measure bulk tombstone/key-change writes on each representative table against the protocol's per-table write ceilings.
- Verify storage exhaustively rather than by representative: after building the full adopted index set at implementation scale, every affected tracked table must satisfy the protocol's per-table baseline storage ceilings.
- Regenerate affected DDL/manifests/goldens and cover both providers with functional and generated-DDL integration tests; the `RelationalMappingVersion` bump this physical change requires is deferred to a dedicated mapping-version ticket rather than owned here; the first such ticket is filed with the follow-on tickets after spike approval and must land no later than the first story that ships a physical index change, and each later independently released batch of physical index changes requires its own bump ticket for that release.
- After emission, verify that the exact generated DDL is semantically identical to the pinned overlay over the benchmark deployment's tables (per-table key columns, PostgreSQL operator classes, deduplication outcomes, and shortened identifiers); tables absent from the benchmark schema are covered by the deterministic emission predicate and the protocol's predicate-level seek verification rather than the overlay comparison or per-index seek measurement. Then rerun the representative read and write matrix against that generated DDL. A mismatch or failed post-implementation gate blocks acceptance rather than being described as run-to-run noise.
- When the predicate is adopted, this ticket merges the adopted design into the normative `change-queries.md`: the tracked namespace index specification, its coverage rule, and any `TrackedChangeAuthorizationSqlEmitter` predicate adaptation, cross-referencing the live mechanism decision Authorization Story 22 records in `auth.md` rather than restating it.
