# MetaEd follow-up: clarify PUT body ID validation

Tracking issue: [METAED-1682](https://edfi.atlassian.net/browse/METAED-1682).
Related DMS change: [DMS-1623](https://edfi.atlassian.net/browse/DMS-1623).

## Problem and proposed change

Generated PUT descriptions say that a body identifier “will be ignored.” The
value does not determine the update target, but malformed or non-string/non-null
IDs still fail validation. This wording can lead clients to expect such values
to be accepted.

Replace the identifier-related sentences with:

> The URL identifier determines the resource to update. The body `id` may be omitted or null. A supplied non-null `id` must be a valid GUID string; its value does not determine the target resource.

Preserve the separate natural-key/cascading-update guidance. Do not make `id`
required in the request schema. DMS accepts strings supported by `Guid.TryParse`,
including a different ID and the empty GUID.

## Acceptance criteria

- Update the generator and its OpenAPI expectations for resource and descriptor
  PUT operations; verify omitted/null IDs and valid differing IDs are described
  consistently, and malformed supplied IDs are not described as unconditionally ignored.
- Publish the corrected descriptions through the normal API schema package
  pipeline, then update consuming DMS packages in a separate change.
- Keep request-schema optionality and runtime behavior unchanged.

This DMS correction does not edit generated schema fixtures or regenerate packages.
The [8.1 changelog](../../docs/changelog/8.1.0.md) explains the validation requirement
while this generator correction is pending.
