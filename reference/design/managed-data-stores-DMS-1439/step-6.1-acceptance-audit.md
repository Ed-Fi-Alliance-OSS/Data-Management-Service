## Focused closure work before calling step 6.1 complete

### G5 — Complete the ten-state HTTP DELETE matrix

The [frontend HTTP test](../../../src/config/frontend/EdFi.DmsConfigurationService.Frontend.AspNetCore.Tests.Unit/Modules/DataStoreManageHttpTests.cs) `It_maps_not_found_failure_and_each_non_created_delete_state` exercises PendingCreate, CreateFailed, PendingDelete and DeleteError. Provider `DataStoreManageHttpTests` exercises Created/Ready, Created/closed, PendingDelete/closed and Deleted/closed. G1d additionally checks CreateError/DeleteError DELETE returns 400, but does not assert their exact state-specific messages. `DataStoreManageDeleteAcceptanceTests.It_preserves_exact_state_and_prioritizes_lifecycle_before_readiness` covers all ten states at the repository boundary; frozen fixture states and GET model tests do not fill missing DELETE pipeline cases.

Complete the controlled HTTP matrix with CreateInProgress, CreateError, DeleteInProgress and DeleteFailed, requiring each approved message/status, no Location, and unchanged aggregate/job/catalog on refusal. CreateError already has external status coverage; CreateInProgress, DeleteInProgress and DeleteFailed DELETE pipeline cases were not located. Do not count the external CreateError case as absent or as exact-message coverage. Prefer extending the existing shared expectations in the two provider HTTP fixtures, retaining Created/204, Deleted/404, absent/404 and readiness precedence. Run only the affected HTTP selections on PostgreSQL and SQL TCP. Do not rerun physical provisioning merely to verify these result mappings. This is a test gap, not a demonstrated implementation bug.

### G6 — Explicit managed sensitive-data canaries

The nine-field HTTP tests prove internal fields are not response members. The generic executor test `Given_a_failure_whose_message_and_payload_carry_secrets` checks exception/payload canaries; provisioner diagnostic tests check safe exception metadata; external fixtures scan captured CMS output for configured credentials/tokens. In the inspected sources these checks do not include the persisted expected source identity as a log/job canary. Test-run progress intentionally prints independently recorded target/identity for residue investigation; that test-owned output is distinct from production CMS logs and must not be confused with an application leak.

Add focused managed-path assertions that the persisted identity, runtime/admin connection canaries and credential-bearing artifact diagnostic canaries do not appear in managed responses, public job responses/error messages or captured structured CMS logs, including a typed failure. Reuse existing handlers/fences and capture seams; verify both formatted messages and structured fields where captured. Keep actual test secrets out of failure output. Run the smallest affected selections. This closes the spec's explicit sentinel assertion requirement; it is not a request for a new logger, production diagnostics redesign or an audit of arbitrary operator-installed sinks.
