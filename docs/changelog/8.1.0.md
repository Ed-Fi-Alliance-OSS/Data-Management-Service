# Changelog: 8.1.0

Brief descriptions of breaking changes and new features in this release, aimed at
integrators upgrading from the previous version. Each entry says what changed and what,
if anything, a client must do differently; the linked design documents carry the full
detail and rationale.

## Breaking changes

- **`POST /connect/revoke` now requires an authenticated caller, and only revokes tokens
  belonging to that caller.** The endpoint previously accepted anonymous requests; it now
  returns `401 Unauthorized` without a valid `Authorization` header. A caller may only
  revoke a token whose `client_id` matches its own — a mismatch is a silent no-op that
  still returns `200 OK`, per RFC 7009. Because every authenticated outcome returns the
  same `200 OK`, confirm a revocation with `POST /connect/introspect` rather than relying
  on the status code. Clients that called `/connect/revoke` anonymously must be updated to
  authenticate. See [CS-AUTH.md](../../reference/design/configuration-service/CS-AUTH.md)
  and [OWASP-AUTH-COVERAGE.md](../OWASP-AUTH-COVERAGE.md).
